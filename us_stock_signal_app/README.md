# PulseEdge

미국 주식 관심종목과 보유종목을 감시하고 RSI, 이동평균선, 거래량, 갭, 돌파/이탈, 평단가 기준 신호를 알려주는 모바일 우선 PWA입니다. 처음 버전은 실거래 주문을 넣지 않고 분석과 알림만 담당합니다.

## 제품 원칙

- 매일 보는 화면은 최소화합니다. 판단에 바로 필요한 `Home`, `Watch`, `Hold`, `Signals`, `Settings`만 둡니다.
- 새 기능은 바로 붙이지 않고 보고서의 개선 후보에 먼저 기록합니다.
- 백테스트와 룰 실험은 사용자 화면보다 내부 검증/보고서 기록 중심으로 유지합니다.
- PulseEdge는 초단타나 실시간 주문 판단용이 아니라 일봉/주봉 기반의 스윙 관찰과 보유종목 점검용입니다.
- 관심종목 분석은 서버에서 병렬 처리하고, 같은 종목/기간 데이터는 짧게 캐시해 요청과 대기 시간을 줄입니다.
- 자동 새로고침은 최소 15분으로 제한하고, Settings에서 캐시와 외부 요청 상태를 확인합니다.
- 로그인 전 단계에서는 브라우저별 익명 ID로 사용자 설정을 분리 저장합니다.

## 차트와 분석 데이터 기준

- 기본 화면 확인은 `provider: demo`로 가능합니다.
- 종목 상세 차트는 TradingView Advanced Chart 위젯을 사용하며 RSI(14)를 기본 표시합니다. `S/R` 모드로 전환하면 PulseEdge 분석 봉과 동일한 데이터로 RSI, 20/60/120일선, 일목/볼린저, 자동 지지·저항선과 사용자 선을 확인할 수 있습니다.
- TradingView 위젯의 출처 표시는 유지하며, 위젯 데이터나 보조지표 값을 PulseEdge 신호 계산에 가져오지 않습니다.
- 공개 빌드에서는 Alpaca를 활성화하지 않습니다. 원시 봉뿐 아니라 파생 RSI·점수도 상업적 외부 제공 허가가 확인되기 전에는 사용하지 않습니다.
- PulseEdge 점수와 자동 지지·저항은 재배포 가능한 시세 공급원을 연결하기 전까지 샘플 데이터로만 동작합니다.
- 앱 화면에는 주식 데이터 기준과 VIX 기준을 작게 표시합니다. VIX는 CBOE 공식 일봉 종가를 우선 사용하고 실패 시 FRED `VIXCLS`로 전환하며, 장중 실시간 공포지수는 아닙니다.
- `Settings > 데이터`에는 TradingView 차트와 PulseEdge 샘플 분석의 차이를 명시합니다.
- 같은 종목/기간의 바 데이터는 8분간 서버 메모리 캐시를 사용합니다.
- `Settings > 데이터`의 `API 보호` 타일은 바 캐시 적중률과 외부 데이터 요청 수를 보여줍니다.

## 공개 시세 공급원 상태

공개 빌드는 Alpaca API를 호출하지 않습니다. TradingView 위젯은 차트 표시와 기본 RSI·수동 드로잉에만 사용하며, iframe 내부 데이터는 PulseEdge 신호 계산에 가져오지 않습니다. 자동 지지·저항과 점수 계산에는 별도로 재배포 및 파생지표 제공이 허용된 OHLCV 공급원이 필요합니다.

현재 후보는 사용자별 토스증권 Open API 연결 또는 상업적 외부 표시가 허용된 시세 공급자입니다. 공급원 확정 전 분석 결과는 샘플로 표시합니다. VIX는 별도 API 키 없이 CBOE 공식 일봉을 우선 가져오고, 실패 시 FRED VIXCLS를 사용합니다.

## 로그인 설정

로그인은 Supabase Auth로 연결합니다. 인증 설정이 있으면 첫 방문에 로그인/회원가입 화면을 먼저 표시하고, 이메일 매직 링크와 선택적인 Google 로그인을 사용할 수 있습니다. `로그인 없이 둘러보기`를 선택한 사용자는 해당 브라우저에서 게스트 모드로 계속할 수 있습니다. 인증 설정이 없거나 연결에 실패하면 앱을 막지 않고 기존 게스트 모드로 전환합니다.

```text
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_PUBLISHABLE_KEY=your_publishable_key
SUPABASE_EMAIL_ENABLED=true
SUPABASE_GOOGLE_ENABLED=false
SUPABASE_SECRET_KEY=your_server_only_secret_key
```

- 브라우저에는 Supabase `publishable key`만 전달합니다. `service_role` 키는 서버 `.env` 또는 호스팅 환경변수에만 저장하고 HTML, JavaScript, API 응답에는 절대 노출하지 않습니다.
- 로그인 토큰은 Supabase `/auth/v1/user`에서 서버가 검증합니다.
- 첫 로그인 때 기존 게스트 관심종목, 보유종목, 동의 기록을 계정으로 복사합니다.
- 다른 기기에서 처음 로그인하면 기존 계정 설정은 유지하고, 그 기기의 게스트 관심종목과 새 보유종목만 한 번 병합합니다.
- 로그인 세션이 남아 있으면 재방문 시 시작 화면 없이 바로 앱으로 들어갑니다.
- 로그아웃하면 첫 로그인 화면으로 돌아가며, 게스트 체험은 사용자가 다시 선택할 수 있습니다.
- Settings의 `계정 및 데이터 삭제`는 로그인 이메일 재입력을 요구하며, Supabase 계정과 PulseEdge 서버·브라우저 데이터를 함께 삭제합니다.
- 비밀번호와 Google OAuth 토큰은 PulseEdge SQLite에 저장하지 않습니다.
- Google 로그인을 켜려면 Supabase와 Google 콘솔에서 OAuth 공급자와 허용 Redirect URL을 먼저 설정한 뒤 `SUPABASE_GOOGLE_ENABLED=true`로 바꿉니다.
- 로컬 테스트 주소와 실제 HTTPS 도메인을 Supabase Redirect URLs에 각각 등록해야 합니다.

## 공개 앱 운영 원칙

- 공개 앱 사용자는 Alpaca API Key를 직접 입력하지 않습니다.
- Alpaca 연결과 현재 신호 엔진은 `PULSEEDGE_MARKET_DATA_PROVIDER=alpaca`로 실행한 개인용 버전에서만 활성화합니다.
- 공개 화면의 상세 차트는 TradingView 위젯을 사용하되, PulseEdge 점수와 신호에 필요한 분석 데이터 제공사는 별도 계약/약관 확인 전까지 확정하지 않습니다.
- 어떤 분석 데이터 제공사를 선택하더라도 API 키는 운영자 서버의 환경변수로만 관리하고, 앱 화면이나 사용자 저장소에 노출하지 않습니다.
- TradingView 차트가 로드되지 않으면 샘플 데이터 기반 PulseEdge 분석 차트를 예비 화면으로 표시합니다.
- 사용자는 관심종목, 보유여부, 평단가, 매수일, 알림 설정만 입력합니다.
- 초기 무료/PWA 테스트는 첫 화면의 `로그인 없이 둘러보기`로 기기별 게스트 저장을 사용할 수 있습니다.
- 로그인 전 게스트 모드에서는 브라우저가 익명 ID를 만들고, 서버는 `user_data/pulseedge.sqlite3`에서 사용자 ID별로 관심종목, 보유종목, 설정을 분리 저장합니다.
- 로그인은 Supabase Auth 세션을 서버에서 검증한 뒤 SQLite 계정 행과 연결합니다. 인증 설정이 없을 때만 앱이 자동으로 게스트 공간을 사용합니다.
- 예전 `user_data/guests/*.json`이 있으면 해당 사용자의 첫 접속 때 SQLite로 자동 이전하며 원본 JSON은 백업으로 남깁니다.
- `config.json`은 `demo`, 대표 관심종목 6개, 보유종목 없음 상태의 공개 기본 템플릿입니다.
- 계정과 사용자 데이터의 직접 삭제 흐름은 구현됐습니다. 공개 출시 전에는 개인정보 처리방침과 별도 데이터 삭제 문의 절차를 확정합니다.
- 사용자 `Settings`에서는 API Key 입력칸을 제거했고, 웹 저장/삭제 API도 차단했습니다. 서버 배포 때는 운영자가 환경변수만 설정합니다.
- 앱 안에는 투자 유의 문구를 노출합니다. PulseEdge는 투자 참고용 분석 도구이며, 신호는 수익 보장이나 매수/매도 지시가 아닙니다.
- 앱 안에는 초단타/분봉/틱 단위 실시간 매매 판단용이 아니라는 문구를 유지합니다.
- Settings에는 접이식 위험 고지를 둡니다. 투자 손실, 신호 한계, 개인 맞춤 자문 아님, 주문 대행 아님, 알림 지연/누락 가능성, 최종 확인 책임을 명시합니다.
- 첫 실행 때 투자 유의 동의를 한 번 받고, 현재 동의 기록은 브라우저 로컬 저장소에 버전과 시간으로 남깁니다. SQLite에는 로그인 연동 때 사용할 동의 기록 테이블을 준비했습니다.
- 데이터 고지에는 TradingView 차트와 샘플 분석의 구분, VIX 일봉 종가 기준을 표시합니다.

## 현재 신호

- 각 종목은 미보유면 `진입점수`, 보유면 `관리강도`를 0-100점으로 표시합니다.
- `진입점수`는 50점을 기본 대기값으로 두고, 55점 이상은 관찰, 62점 이상은 반등체크, 70점 이상은 자리검토, 85점 이상이나 강한 이벤트가 붙은 70점대는 진입검토로 봅니다.
- 보유 `관리강도`는 내부를 `방어`, `수익보호`, `이벤트`로 나눠 계산합니다. 최종 관리강도는 방어와 수익보호 중 더 급한 쪽에 실적/VIX 같은 이벤트를 일부 더해 표시합니다.
- `Settings > 점수 기준표`에서 Watch 진입점수와 Hold 관리강도 구간을 접어서 확인할 수 있습니다.
- `방어`는 손실률, 고정손절, 매수일 이후 S1 지지선 이탈, 60/120일선 이탈, 하락 거래량을 봅니다.
- `수익보호`는 +10/+20/+30 수익 구간, 이평선 과열 이격, RSI 과열, 트레일링, 저항선 근접을 봅니다.
- 점수는 알림 신호뿐 아니라 RSI 구간, 거래량 배수, 20/60/120일선 위아래, 20/60일선 이격률, 볼린저밴드 위치, 일목 구름 위치 같은 상태 점수를 함께 반영합니다.
- RSI는 25/30/35/40/45/55/60/65/70 구간으로 쪼개서 과매도는 가점, 65 이상은 감점, 70 이상은 큰 감점으로 처리합니다.
- 거래량은 0.5/0.8/1.0/1.2/1.5/2.0배 구간으로 나눠, 1.2배 이상부터 확인 점수를 주고 너무 낮으면 신뢰도를 낮춥니다.
- 일목 구름 회복은 단독으로는 반등 후보로만 보고, RSI 적정 구간과 거래량 확인이 같이 붙을 때만 기회 후보로 올립니다.
- 자동 지지/저항선은 미보유 종목은 최근 180일 기준, 보유 종목은 매수일 이후 기준으로 계산합니다.
- 보유 종목은 매수 후 고점/저점, 매수일 고점/저점, 평단가를 함께 후보선으로 잡아 가까운 방어선과 위쪽 저항을 봅니다.
- 미보유 종목에서 신호가 없으면 `대기`로 표시합니다.
- 미보유 종목은 진입 검토 관점으로 `관심`, `공포관심`, `반등후보`, `기회후보`, `돌파후보`를 우선 사용합니다.
- 보유 종목은 계좌 방어와 수익 보호 관점으로 `수익관리`, `주의`, `점검필요`, `방어검토`, `위험`을 우선 사용합니다.
- RSI 30 이하, RSI 25 이하, RSI 회복, RSI 과열/과열 식음
- 거래량 급증, 상승 거래량, 하락 거래량
- 20/60/120일선 이탈과 회복
- 20/60/120일선 대비 이격률
- 20/60 골든크로스와 데드크로스
- 볼린저밴드와 일목균형표 차트 오버레이
- 볼린저밴드 하단 터치/회복, 일목 구름 회복/이탈
- 60/120일 신고가와 신저가
- 갭상승, 갭하락, 갭하락 + 거래량
- 보유종목 평단가 기준 손익, 손절 검토, 수익 보호, 트레일링 경고
- 보유종목은 설정 손절가와 고점 대비 트레일링 기준가를 계산해 카드와 상세 화면에 표시합니다.

- 구조선 이탈 신호가 있으면 `방어선` 칸에 최근 깨진 구조선을 우선 표시해 왜 구조 방어 검토인지 보이게 합니다.
- 위험선까지 6% 이내면 방어선 확인, 3% 이내면 위험선 근접, 위험선 이탈 시 방어검토 신호를 냅니다.

- 보유 수익 신호는 `+10%`, `+20%`, `+30%` 중 가장 높은 구간 하나만 적용해 관리강도가 과하게 누적되지 않게 합니다.
- 보유 관리강도는 안정 요인이 충분하면 30~40점대까지 내려갈 수 있고, 80 이상은 관리강화, 90 이상은 강한관리 구간으로 봅니다.

- 새 신호는 `관심/보유/시장 관점 + 티커 + 신호 종류 + 거래일` 기준으로 구분하고, 같은 신호는 같은 거래일에 한 번만 기록/알림합니다.
- 앱을 처음 열어 분석한 신호는 로그로만 남기고, 이후 새로 발생한 즉시 알림 신호만 브라우저 알림 대상으로 봅니다.
- 보유 위험/수익관리 신호, 시장 신호, 관심 진입 신호 순서로 우선 처리합니다.

- `수익형` 룰은 다음 거래일 시가 진입, -8% 손절, +15% 25% 익절, +25% 25% 익절, 남은 물량 -10% 트레일링, 최대 90거래일 보유입니다.
- `수익형+구조손절` 룰은 수익형에 S1 지지선 1% 이탈 + -6% 손실 확인, 또는 60일선 2거래일 이탈 + -6% 손실 확인 시 다음 거래일 시가 청산을 추가한 방어형 비교 옵션입니다.
- `균형형` 룰은 -7% 손절, +12%/+20% 분할익절, -8% 트레일링, 최대 60거래일 보유로 비교할 수 있습니다.

## 모바일 앱처럼 쓰기

- 화면은 모바일 우선 다크모드로 구성되어 있습니다.
- PWA 매니페스트, 서비스워커, 192/512px PNG 아이콘, iPhone용 `apple-touch-icon`을 포함합니다.
- `Settings > 앱 설치`에서 현재 실행 상태, 현재 주소, 폰 접속 주소를 확인할 수 있습니다.
- 브라우저에서 홈 화면에 추가하면 PWA처럼 실행할 수 있습니다.
- Android Chrome은 설치 버튼이 가능할 때 앱 설치 프롬프트를 띄우고, iPhone은 Safari 공유 버튼에서 `홈 화면에 추가`를 사용합니다.
- 하단 탭은 `Home`, `Watch`, `Hold`, `Signals`, `Settings`입니다.
- `Home`의 `오늘 볼 종목`은 Watch 기준 진입점수에 RSI, 거래량, 지지선 근접, 저항선 근접, 시장 리스크를 보정해 상위 3개를 보여줍니다.
- `Home`의 `오늘의 핵심`은 즉시/요약 알림을 합쳐 보유, 시장, 관심 관점별 핵심 1개씩만 짧게 보여줍니다.
- 헤더의 알림 버튼은 `알림 켜기`, `알림 켜짐`, `알림 차단됨`, `알림 불가` 상태를 표시하고, 짧은 설명을 함께 보여줍니다.
- `Watch`와 `Hold`는 차트 없는 압축 카드로 여러 종목을 빠르게 훑습니다.
- 보유 종목도 관심목록에서 빠지지 않지만, `Watch`에서는 미보유라고 가정한 일반 진입점수로 보고 `Hold`에서는 실제 보유 기준 관리강도로 봅니다.
- `Watch` 상단에서 티커를 바로 추가할 수 있고, 카드의 삭제 버튼으로 일반 관심종목을 바로 정리할 수 있습니다.
- `Watch`는 전체/진입검토/반등체크/관심/주의/대기숨김 필터와 점수, 지지선, 저항선, RSI, 거래량, 등락률, 이름순 정렬을 제공합니다.
- `Home`의 `진입 관찰`은 Watch의 실제 점수 단계 이름을 사용해 화면 간 표현이 어긋나지 않게 합니다.
- 종목 카드를 누르면 큰 차트, 점수 근거, 핵심 지표, 신호 이유, 보유 정보를 보는 상세 화면이 열립니다.
- 상세 화면은 가까운 자동 지지선/저항선과 강도를 보여주고, 차트에도 `S1/R1` 수평선을 표시합니다.
- 상세 차트는 일봉/주봉, 3개월/6개월/1년/전체 기간을 바로 전환할 수 있습니다.
- `BB`, `일목` 버튼으로 볼린저밴드와 일목균형표를 켜고 끌 수 있습니다.
- `선` 버튼을 누른 뒤 차트의 가격 영역을 드래그하면 추세선을 그릴 수 있고, `삭제`로 최근 선을 지울 수 있습니다.
- 차트 위에서 휠/터치패드 또는 모바일 핀치로 확대/축소하고, 드래그로 과거 구간을 볼 수 있습니다.
- `Settings`에서 티커를 입력해 관심종목을 편집하고, 칩의 삭제 버튼으로 정리할 수 있습니다.
- `Settings`는 자주 쓰는 설치/데이터/관심종목 칩만 펼쳐두고, 원본 목록 편집, 신호 기준, 점수표, 보유종목, 용어, 투자 유의, 알림 선택은 접이식으로 줄입니다.
- `Settings`에서 각 신호의 알림 모드를 `즉시`, `요약`, `기록`, `끔`으로 선택할 수 있습니다.
